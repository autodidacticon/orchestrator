On `session.created` the plugin runs `session-start.mjs` once and caches its line; on the first `chat.message` of that session it appends the line to the user's existing text part (never pushes a new part: one without id/sessionID/messageID fails the run with "invalid user part before save"), so the notice is saved with the message and stays in context, as the Claude Code and Codex SessionStart stdout does; it also calls `client.tui.showToast` so the operator sees it. The system-prompt hook is not used (experimental, re-run every step). When the script prints nothing, the message is untouched. No session-end analog (document that the attachment ends on stdio close with reason `sessionEnded`). The plugin is installed by copying into `~/.config/opencode/plugins/`; `--pure` disables it, which only affects worker launches.
- [x] 1.4 Start-mode handling as in the Codex skills: `start` with `mode: spawn` when no daemon runs and no `runner.mode` is set, until the opencode work loop lands (next issue updates the text).
