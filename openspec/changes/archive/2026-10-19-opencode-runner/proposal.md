## Why

Nothing spawns `opencode run`. Without a per-launch MCP registration the agent has no orchestrator tools; without a permission ruleset every `ask` is a silent auto-reject; without a usage parser every opencode launch is unpriced; without stdin redirected the run hangs forever.

## What Changes

1. `DEFAULT_OPENCODE_COMMAND` in src/runner/command.ts: `opencode run --format json {pure} --print-logs --log-level WARN -m {model} {variant} < {brief}`. `{variant}` is `--variant {effort}` (empty when effort is unset), `{pure}` is `--pure` under `runner.opencode.pure`. No positional message: the brief on stdin is the whole message. `hasModelSlot`/`hasEffortSlot` true; no `{allowedTools}` slot.
2. `OpenCodeRunner extends SubprocessRunner` with a `compose` closure (as the Codex runner) and a `spawn` that adds to the launch environment: `OPENCODE_CONFIG_CONTENT` = the per-launch config JSON; `XDG_DATA_HOME=<worktree>/.orchestrator/opencode-data` when `runner.opencode.dataDir` is `launch`; `XDG_CONFIG_HOME=<worktree>/.orchestrator/opencode-config` (an empty dir) when `ignoreUserConfig` is true. The config JSON carries `mcp.orchestrator { type: local, command: [shim.command, ...shim.args], timeout: <see the decided timeout below> }` with no `environment` block (the shim reads ORCH_API, ORCH_LAUNCH_ID, ORCH_TOKEN, ORCH_RETRY_WINDOW_MS, ORCH_COMMIT_POLICY from the inherited agent environment: no token on argv, no file to protect), `snapshots: false` unless `runner.opencode.snapshots`, `share: "disabled"`, and the permission ruleset. The same JSON is also written to `.orchestrator/opencode.json` (0600, for `opencode mcp list` style debugging and for the work loop), never passed as a path.
3. Permissions: `runner.opencode.permission: derived` (default) emits `{ "*": "ask", read/glob/grep/list/edit: "allow", "bash": { "*": "ask", <one "allow" per derived rule> } }` where a derived `Bash(x:*)` rule becomes the pattern `"x *"` and `Bash(x)` becomes `"x"`, plus `"git *": "allow"`; the orchestrator MCP tools get `"orchestrator_*": "allow"`. `allow` emits `{ "*": "allow" }`. An auto-rejected command therefore surfaces to the agent as a tool error the brief tells it to turn into a `needsAccess` question (brief issue).
4. `parseOpenCodeUsage(text)`: tail-bounded, line-oriented, parse each `step_finish` line, sum `tokens.input + tokens.cache.read` into `input`, `cache.read` into `cachedInput`, `cache.write` into `cacheWriteInput`, `output`, `reasoning` into `reasoningOutput`, and `cost` into `costUsd`; `source: 'opencode'` (added to `UsageSource`); `turns` is the count of `step_finish` lines with `reason: "stop"`; no `durationMs`. `OpenCodeRunner.readUsage` reads the launch log like the other runners.
5. src/main.ts registers `opencode: new OpenCodeRunner({...})` reading `orch.effective().config.runner.opencode` at every spawn; `src/index.ts` exports the runner and parser. `composeOpenCodeCommand(launch, policy)` and `openCodeConfig(launch, settings, allowedTools, shim)` are exported for the work loop.
6. Fixtures: test/fixtures/opencode/ already holds the evidence (commit cc43c94 on main): events/{A-stdin,C2,D4,E-badmodel,F1-ask,F2-deny,H1,I1,SA-proj2,R1,T1-T4,Y2}.jsonl, events/{D4,F1-ask,K2,SA-proj}.err, configs/ (probe configs, mcp-mini.mjs, inject-plugin.js), brief-run/ (fake-shim.mjs, brief-q3.md, the three Q3 runs) and README.md. Those files were redacted once before they were saved (scratch paths replaced by `<scratch>`, the home directory by `~`, GitLab model ids by `duo-chat-<model>`); the README says so. This change edits none of them: tests read them in place, and the only allowed addition is a section in README.md mapping files to tests. Parser unit tests ship here; the classifier tests ship with the diagnosis issue.
7. MCP call timeout (decided 2026-10-19, probed: test/fixtures/opencode/events/T1-T4.jsonl): an MCP tool call is cut after 60 000 ms by default (`MCP error -32001: Request timed out`); `mcp.timeout.execution` from the published schema is dropped by 1.18.30 (WARN "Omitted native setting that cannot be represented in V1"); the per-server `mcp.<id>.timeout` is honoured (a 75 s call completed under `timeout: 900000`). The per-launch config therefore sets `mcp.orchestrator.timeout` to `maxWaitMs + 60000`, overridable by `runner.opencode.toolTimeoutMs` (the analog of `codexToolTimeoutSec`), and never emits `mcp.timeout.execution`. The spec records the 60 s default and the key that works. Cost accepted: the same key is the startup tools-fetch timeout, so a shim that hangs at startup is noticed late; one whose command cannot start still fails immediately (D4).
